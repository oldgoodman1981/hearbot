# Архитектура Hearbot

## Общая схема

```
┌──────────────────┐        WebSocket (PCM-чанки)        ┌────────────────────┐
│  Windows-клиент  │ ──────────────────────────────────▶ │                    │
│ customtkinter  │ ◀────────────────────────────────── │   FastAPI-сервер   │
└──────────────────┘   JSON: ready / final / control     │                    │
                                                         │ ConnectionManager  │
┌──────────────────┐        WebSocket (PCM-чанки)        │   ├─ клиенты       │
│  Android-клиент  │ ──────────────────────────────────▶ │   ├─ метрики       │
│    Kivy + AR     │ ◀────────────────────────────────── │   └─ события       │
└──────────────────┘                                     │         │          │
                                                         │         ▼          │
┌──────────────────┐        GET /api/state               │   STTProvider      │
│  Панель /admin   │ ◀────────────────────────────────── │    ├─ Dummy        │
│  браузер         │ ──────────────────────────────────▶ │    ├─ Vosk ────────┼──▶ локальная модель
└──────────────────┘  POST /api/clients/{id}/control     │    └─ Yandex ──────┼──▶ SpeechKit REST
                                                         └────────────────────┘
```

Каждый клиент работает независимо: отдельное WebSocket-соединение, отдельная
сессия распознавания. Клиенты не общаются друг с другом.

## Компоненты сервера

| Файл | Ответственность |
|------|-----------------|
| `server/main.py` | HTTP `/health`, WebSocket `/ws/stt`, страница `/admin`, лимиты реплики |
| `server/config.py` | чтение настроек из окружения, загрузка `.env` |
| `server/manager.py` | реестр клиентов, статистика, история событий, команды управления |
| `server/admin_api.py` | REST API панели: `/api/state`, `/api/clients`, `/api/clients/{id}/control` |
| `server/static/dashboard.html` | веб-панель мониторинга (Tailwind + ванильный JS) |
| `server/stt/base.py` | абстракция `STTProvider` |
| `server/stt/dummy.py` | заглушка для разработки |
| `server/stt/vosk.py` | офлайн-распознавание на локальной модели Vosk |
| `server/stt/yandex.py` | Yandex SpeechKit REST v1 |
| `server/stt/factory.py` | выбор провайдера по `STT_PROVIDER` |

## Жизненный цикл реплики

```
клиент                     сервер                         провайдер
  │  connect /ws/stt         │                                │
  │─────────────────────────▶│  create_provider()             │
  │                          │───────────────────────────────▶│
  │                          │  start(lang)                   │
  │◀──── ready ──────────────│                                │
  │                          │                                │
  │  binary chunk (50 мс)    │                                │
  │─────────────────────────▶│  send_audio(chunk)             │
  │         ...              │───────────────────────────────▶│
  │                          │                                │
  │  {"type": "stop"}        │                                │
  │─────────────────────────▶│  finish()                      │
  │                          │───────────────────────────────▶│
  │                          │◀──────── текст ────────────────│
  │◀──── final {text} ───────│                                │
  │                          │  start(lang)  — новая реплика  │
```

Одно соединение переиспользуется для нескольких реплик: после `final` сервер
сразу готов принимать следующую.

## Провайдеры

Все провайдеры реализуют три асинхронных метода:

```python
async def start(language: str) -> None
async def send_audio(chunk: bytes) -> None
async def finish() -> str
async def close() -> None
```

- **Dummy** — считает байты, возвращает длительность. Нужен для тестов и
  разработки UI без расхода бесплатных минут.
- **Vosk** — офлайн-распознавание. `vosk.Model` загружается один раз на процесс
  и кэшируется в модуле; на каждую реплику создаётся свой `KaldiRecognizer`.
  Декодирование и загрузка модели выполняются в отдельных потоках
  (`asyncio.to_thread`), чтобы не блокировать event loop. Промежуточные
  результаты, которые Vosk отдаёт на паузах, накапливаются и склеиваются с
  финальным.
- **Yandex** — накапливает PCM в `bytearray`, при `finish()` отправляет один
  POST в `speech/v1/stt:recognize` с заголовком `Authorization: Api-Key ...`.
  Возвращает только финальный текст.

### Почему REST, а не стриминг

Yandex SpeechKit v1 — простой синхронный API, идеален для MVP. Минусы:
нет частичных результатов и вся реплика держится в памяти. Следующий шаг —
**gRPC API v3** (`stt.api.cloud.yandex.net:443`, `Recognizer.StreamingRecognize`),
который даёт partial-результаты и снижает задержку. Для этого провайдер
получит отдельный класс, а `main.py` — отправку `partial`-сообщений клиентам.

## Клиенты

### Windows

- `customtkinter` — тёмная тема в стиле панели `/admin` без ручной отрисовки
  виджетов; палитра задана константами (`BG`, `PANEL`, `ACCENT`, …).
- `PyAudio` — callback-режим, чанки по 800 фреймов (50 мс); RMS каждого чанка
  сглаживается и показывается полосой уровня микрофона.
- `websocket-client` — два потока: writer (очередь исходящих) и reader.
- UI обновляется через `Tk.after`, так как колбэки приходят из фоновых потоков.
- Состояние связи показывается «пилюлей»: «Не подключён» → «Подключение…» →
  «Онлайн · provider» / «Нет связи»; таймер реплики обновляется каждые 80 мс.
- Команды панели (`control`) выполняются в UI-потоке через тот же `after`.

### Android

- `Kivy` — кроссплатформенный UI на Python; тёмная палитра, собственные
  виджеты `Card`, `StatusDot`, `LevelMeter`, `RoundRecordButton` рисуются
  через `kivy.graphics` (закруглённые панели, пульсирующее кольцо записи).
- `pyjnius` + `android.media.AudioRecord` — запись PCM 16-bit mono 16 кГц.
- `websocket-client` + `WebSocketApp.run_forever` в фоновом потоке.
- Разрешения `RECORD_AUDIO` и `INTERNET` запрашиваются при старте.
- На десктопе вместо `AudioRecord` используется `sounddevice` (если установлен) —
  удобно отлаживать интерфейс без сборки APK.
- Сообщения сервера приходят из фонового потока и передаются в UI через
  `Clock.schedule_once`; таймер и уровень микрофона обновляются 10 раз в секунду.

## Панель управления

`server/manager.py` хранит `ClientSession` для каждого активного WebSocket:
ID, платформу, IP, язык, время подключения, длительность аудио, последний
текст и признак записи. Каждая сессия имеет `asyncio.Lock` — единственную
точку отправки сообщений, чтобы обработчик реплики и админ-команда не писали
в сокет одновременно.

`ConnectionManager` дополнительно ведёт:

- агрегированную статистику (uptime, число реплик, секунды аудио, ошибки);
- кольцевую историю событий (`deque(maxlen=100)`): подключение, финальный
  текст, ошибка, отключение.

`admin_api.py` отдаёт снимок состояния (`GET /api/state`) и принимает команды
(`POST /api/clients/{id}/control`). Фронтенд опрашивает `/api/state` раз в
секунду, поэтому отдельный WebSocket для панели не нужен.

Команды управления:

| Действие | Что делает сервер | Что делает клиент |
|----------|-------------------|-------------------|
| `stop_recording` | шлёт `control`, помечает сессию как «пауза» | останавливает микрофон и шлёт `stop` |
| `start_recording` | шлёт `control`, помечает сессию как «запись» | запускает микрофон |
| `disconnect` | закрывает WebSocket (код 1000) | получает штатное закрытие |

## Конфигурация

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `STT_PROVIDER` | `dummy` | `dummy`, `vosk` или `yandex` |
| `STT_LANGUAGE` | `ru-RU` | язык по умолчанию |
| `VOSK_MODEL_PATH` | `models/vosk-model-small-ru-0.22` | путь к модели Vosk |
| `YANDEX_API_KEY` | — | API-ключ сервисного аккаунта |
| `YANDEX_FOLDER_ID` | — | каталог Yandex Cloud |
| `MAX_UTTERANCE_SECONDS` | `30` | лимит длины реплики |
| `ALLOW_ANONYMOUS` | `true` | разрешать подключения без токена |
| `HEARBOT_TOKEN` | — | общий токен при `ALLOW_ANONYMOUS=false` |
| `HEARBOT_ADMIN_TOKEN` | — | токен панели; пусто — доступ без пароля |

## Безопасность

- В продакшене сервер должен работать за TLS-терминатором (`wss://`).
- Текущая авторизация клиентов — общий токен в query-параметре. Для
  полноценного продукта нужен JWT/OAuth с привязкой к пользователю и квотами.
- Панель `/admin` защищается `HEARBOT_ADMIN_TOKEN`: браузер хранит токен в
  `localStorage` и отправляет его в заголовке `X-Admin-Token`. Пустое
  значение оставляет панель открытой — допустимо только для локальной сети.
- Обязательно ограничивайте размер входящих сообщений и частоту подключений
  на уровне reverse-proxy (nginx, Caddy).

## План развития

1. VAD на клиенте или сервере (`webrtcvad`) — экономия трафика и бесплатных минут.
2. Yandex gRPC v3 — partial-результаты в реальном времени.
3. Дополнительные провайдеры: Google STT, Azure Speech.
4. JWT-аутентификация и квоты на пользователя.
5. Docker-образ сервера и CI-сборка APK.
