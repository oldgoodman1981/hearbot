# Архитектура Hearbot

## Общая схема

```
┌──────────────────┐        WebSocket (PCM-чанки)        ┌──────────────────┐
│  Windows-клиент  │ ──────────────────────────────────▶ │                  │
│ tkinter + PyAudio│                                     │  FastAPI-сервер  │
└──────────────────┘ ◀────────────────────────────────── │                  │
                       JSON: ready / final / error       │  STTProvider     │
                                                         │   ├─ Dummy       │
┌──────────────────┐        WebSocket (PCM-чанки)        │   └─ Yandex ─────┼──▶ SpeechKit REST
│  Android-клиент  │ ──────────────────────────────────▶ │                  │
│    Kivy + AR     │ ◀────────────────────────────────── │                  │
└──────────────────┘                                     └──────────────────┘
```

Каждый клиент работает независимо: отдельное WebSocket-соединение, отдельная
сессия распознавания. Клиенты не общаются друг с другом.

## Компоненты сервера

| Файл | Ответственность |
|------|-----------------|
| `server/main.py` | HTTP `/health`, WebSocket `/ws/stt`, разбор команд, лимиты реплики |
| `server/config.py` | чтение настроек из окружения, загрузка `.env` |
| `server/stt/base.py` | абстракция `STTProvider` |
| `server/stt/dummy.py` | заглушка для разработки |
| `server/stt/yandex.py` | Yandex SpeechKit REST v1 |
| `server/stt/factory.py` | выбор провайдера по `STT_PROVIDER` |

## Жизненный цикл реплики

```
клиент                     сервер                         провайдер
  │  connect /ws/stt         │                                │
  │─────────────────────────▶│  create_provider()             │
  │                          │───────────────────────────────▶│
  │                          │  start(lang)                   │
  │◀──── ready ──────────────│                                │
  │                          │                                │
  │  binary chunk (50 мс)    │                                │
  │─────────────────────────▶│  send_audio(chunk)             │
  │         ...              │───────────────────────────────▶│
  │                          │                                │
  │  {"type": "stop"}        │                                │
  │─────────────────────────▶│  finish()                      │
  │                          │───────────────────────────────▶│
  │                          │◀──────── текст ────────────────│
  │◀──── final {text} ───────│                                │
  │                          │  start(lang)  — новая реплика  │
```

Одно соединение переиспользуется для нескольких реплик: после `final` сервер
сразу готов принимать следующую.

## Провайдеры

Все провайдеры реализуют три асинхронных метода:

```python
async def start(language: str) -> None
async def send_audio(chunk: bytes) -> None
async def finish() -> str
async def close() -> None
```

- **Dummy** — считает байты, возвращает длительность. Нужен для тестов и
  разработки UI без расхода бесплатных минут.
- **Yandex** — накапливает PCM в `bytearray`, при `finish()` отправляет один
  POST в `speech/v1/stt:recognize` с заголовком `Authorization: Api-Key ...`.
  Возвращает только финальный текст.

### Почему REST, а не стриминг

Yandex SpeechKit v1 — простой синхронный API, идеален для MVP. Минусы:
нет частичных результатов и вся реплика держится в памяти. Следующий шаг —
**gRPC API v3** (`stt.api.cloud.yandex.net:443`, `Recognizer.StreamingRecognize`),
который даёт partial-результаты и снижает задержку. Для этого провайдер
получит отдельный класс, а `main.py` — отправку `partial`-сообщений клиентам.

## Клиенты

### Windows

- `tkinter` — UI без внешних зависимостей.
- `PyAudio` — callback-режим, чанки по 800 фреймов (50 мс).
- `websocket-client` — два потока: writer (очередь исходящих) и reader.
- UI обновляется через `Tk.after`, так как колбэки приходят из фоновых потоков.

### Android

- `Kivy` — кроссплатформенный UI на Python.
- `pyjnius` + `android.media.AudioRecord` — запись PCM 16-bit mono 16 кГц.
- `websocket-client` + `WebSocketApp.run_forever` в фоновом потоке.
- Разрешения `RECORD_AUDIO` и `INTERNET` запрашиваются при старте.
- На десктопе вместо `AudioRecord` используется `sounddevice` (если установлен) —
  удобно отлаживать интерфейс без сборки APK.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `STT_PROVIDER` | `dummy` | `dummy` или `yandex` |
| `STT_LANGUAGE` | `ru-RU` | язык по умолчанию |
| `YANDEX_API_KEY` | — | API-ключ сервисного аккаунта |
| `YANDEX_FOLDER_ID` | — | каталог Yandex Cloud |
| `MAX_UTTERANCE_SECONDS` | `30` | лимит длины реплики |
| `ALLOW_ANONYMOUS` | `true` | разрешать подключения без токена |
| `HEARBOT_TOKEN` | — | общий токен при `ALLOW_ANONYMOUS=false` |

## Безопасность

- В продакшене сервер должен работать за TLS-терминатором (`wss://`).
- Текущая авторизация — общий токен в query-параметре. Для полноценного
  продукта нужен JWT/OAuth с привязкой к пользователю и квотами.
- Обязательно ограничивайте размер входящих сообщений и частоту подключений
  на уровне reverse-proxy (nginx, Caddy).

## План развития

1. VAD на клиенте или сервере (`webrtcvad`) — экономия трафика и бесплатных минут.
2. Yandex gRPC v3 — partial-результаты в реальном времени.
3. Дополнительные провайдеры: Google STT, Azure Speech, Vosk (self-hosted).
4. JWT-аутентификация и квоты на пользователя.
5. Docker-образ сервера и CI-сборка APK.
