# Протокол Hearbot

## Транспорт

- WebSocket, путь `/ws/stt`.
- Query-параметры:
  - `lang` — язык распознавания в формате BCP-47 (`ru-RU`, `en-US`). Необязателен.
  - `token` — общий токен доступа. Обязателен, только если на сервере
    `ALLOW_ANONYMOUS=false`.
- Пример: `ws://127.0.0.1:8000/ws/stt?lang=ru-RU`

## Аудио

| Параметр | Значение |
|----------|----------|
| Формат | PCM signed 16-bit little-endian (`pcm_s16le`) |
| Каналы | 1 (mono) |
| Частота | 16 000 Гц |
| Размер чанка | рекомендуется 50 мс = 800 фреймов = 1600 байт |

Бинарные WebSocket-сообщения содержат только аудио, без заголовков.

## Сообщения

### Сервер → клиент

#### `ready`

Приходит сразу после подключения.

```json
{
  "type": "ready",
  "provider": "dummy",
  "language": "ru-RU",
  "sample_rate": 16000,
  "format": "pcm_s16le_mono",
  "max_utterance_seconds": 30
}
```

#### `partial`

Промежуточный результат. Сейчас не отправляется (REST-провайдер возвращает
только финал), но зарезервирован для gRPC-стриминга.

```json
{ "type": "partial", "text": "привет как", "is_final": false }
```

#### `final`

Финальный результат текущей реплики. После него сервер готов принимать
аудио следующей реплики.

```json
{
  "type": "final",
  "text": "Привет, как дела?",
  "is_final": true,
  "audio_seconds": 3.42
}
```

Если аудио не было, `text` пустой:

```json
{ "type": "final", "text": "", "is_final": true, "audio_seconds": 0 }
```

#### `error`

Ошибка распознавания или нарушение лимитов. Соединение при этом остаётся
открытым, кроме ошибки создания провайдера (тогда сервер закрывает его).

```json
{ "type": "error", "message": "recognition failed", "is_final": true }
```

Возможные сообщения:

| `message` | Причина |
|-----------|---------|
| `utterance too long` | реплика превысила `MAX_UTTERANCE_SECONDS`, буфер сброшен |
| `recognition failed` | облачный API вернул ошибку |
| текст исключения | провайдер не смог инициализироваться (нет ключей) |

#### `pong`

Ответ на `ping`.

```json
{ "type": "pong" }
```

### Клиент → сервер

#### Бинарный чанк

Любое бинарное сообщение считается аудио и добавляется в текущую реплику.

#### `stop`

Завершает реплику и запускает распознавание.

```json
{ "type": "stop" }
```

Допустима короткая форма — просто строка `stop` (сервер разберёт её как
`{"type": "stop"}`).

#### `ping`

Проверка соединения.

```json
{ "type": "ping" }
```

## Коды закрытия WebSocket

| Код | Значение |
|-----|----------|
| `1000` | нормальное завершение |
| `1011` | внутренняя ошибка сервера / провайдер не создан |
| `4401` | неверный или отсутствующий токен |

## Пример сессии

```
C: (connect) ws://127.0.0.1:8000/ws/stt?lang=ru-RU
S: {"type":"ready","provider":"dummy","language":"ru-RU",...}
C: <binary 1600 bytes>
C: <binary 1600 bytes>
C: <binary 1600 bytes>
C: {"type":"stop"}
S: {"type":"final","text":"...","is_final":true,"audio_seconds":0.15}
```

## Ограничения

- Максимум `MAX_UTTERANCE_SECONDS` аудио на реплику (по умолчанию 30 с).
- При превышении лимита буфер сбрасывается, клиент получает `error`.
- Аудио должно быть именно 16 кГц; ресемплинг выполняет клиент.
